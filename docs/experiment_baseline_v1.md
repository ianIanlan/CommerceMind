# CommerceMind 实验基线 v1

本报告记录第一版冻结实验结果。数据均为合成客服样本，由项目作者单人标注；它们用于发现回归和比较方案，不代表生产准确率。

## 1. 冻结原则

- `intent_holdout_v1.jsonl` 和 `orchestration_holdout_v1.jsonl` 在运行前冻结。
- 本报告记录结果后，不再依据 v1 错误样本修改标签或规则。
- 下一轮模型、Embedding 或路由优化必须使用新建的 holdout v2 评价泛化。
- 报告保存数据集 SHA-256，使结果能对应到唯一输入版本。

## 2. 意图识别

### 开发基线集

30 条直接表达样本：

| 方案 | Accuracy | Macro-F1 |
|---|---:|---:|
| 关键词规则 | 90.00% | 84.17% |
| 轻量字符 Embedding | 50.00% | 45.00% |
| Embedding + 关键词 | 60.00% | 56.21% |

### 冻结 holdout v1

- 数据集：20 条，每个意图一条；包含隐含表达、口语和业务细节。
- SHA-256：`2c68252a0e05c29e2e18e32399528b5a681701f3b1da12fe486e87efb6d88801`

| 方案 | Accuracy (Wilson 95% CI) | Macro-F1 |
|---|---:|---:|
| 关键词规则 | 20.00% [8.07%, 41.60%] | 15.59% |
| 轻量字符 Embedding | 25.00% [11.19%, 46.87%] | 16.25% |
| Embedding + 关键词 | 25.00% [11.19%, 46.87%] | 16.25% |

结论：规则在模板化表达上表现较高，但对未知表达泛化很弱；当前轻量 Embedding 不能作为可靠语义兜底。需要在 v2 上比较真实中文 Embedding 和 LLM，不能通过继续增加同义词规则宣称问题已解决。

## 3. Agent 编排

### 开发回归集

20 条样本，规则曾依据错误样本调整：

| 方案 | 精确匹配 | 领域召回 | 多领域精确匹配 |
|---|---:|---:|---:|
| 仅主 Agent | 45.00% | 64.52% | 0.00% |
| 条件式 Multi-Agent | 100.00% | 100.00% | 100.00% |

该结果只能用于回归，不能证明泛化。

### 冻结 holdout v1

- 数据集：12 条，其中 7 条为多领域请求。
- SHA-256：`8b17d9d34b4a6a99fbd5c1713caef28ecfac57d1f19a7ecf1c846aae77bdad0d`

| 方案 | 精确匹配 (Wilson 95% CI) | Micro-F1 | 领域召回 | 多领域精确匹配 |
|---|---:|---:|---:|---:|
| 仅主 Agent | 41.67% [19.33%, 68.05%] | 77.42% | 63.16% | 0.00% |
| 条件式 Multi-Agent | 66.67% [39.06%, 86.19%] | 88.24% | 78.95% | 42.86% |

结论：条件式 Multi-Agent 在冻结集上仍提升领域覆盖和 Micro-F1，因此“复合请求需要辅助 Agent”获得了初步证据；但多领域精确匹配仅 42.86%，关键词式辅助路由仍不可靠。

## 4. RAG 与任务状态机

- RAG 数据 22 条：查询扩展 + 领域过滤的 Hit@1 为 73.68%，基础词法为 57.89%；当前仍是开发集结果。
- 任务级确定性检查 6/6 通过，包括订单归属、两阶段确认、幂等、地址边界、人工工单和支付渠道失败不伪报成功。
- Stripe 适配器已通过 MockTransport 与领域状态机测试，但尚未使用新的 Stripe Test Key 完成远端沙箱调用。

## 5. 下一轮预注册对照

在查看 holdout v2 结果前固定以下方案：

1. 当前关键词规则；
2. 当前轻量字符 Embedding；
3. 中文语义 Embedding；
4. LLM 单路；
5. LLM + 中文 Embedding + 关键词的生产融合。

统一报告 Accuracy、Macro-F1、Wilson 95% CI、P50/P95 延迟、失败率和单次请求成本。Multi-Agent 额外报告领域召回、多余 Agent 率、工具越权率和每请求 Agent 数。
