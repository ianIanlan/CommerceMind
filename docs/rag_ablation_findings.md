# RAG 检索消融实验结论

## 实验设置

- 数据：22 条独立查询，其中 19 条有对应政策，3 条知识库不可回答。
- 知识域：售后、订单、账单、技术和通用政策。
- 指标：Hit@1、Hit@3、MRR、拒答准确率、错域率和 P95 检索延迟。
- 检索器：本地演示模式的轻量词法检索，不代表 Chroma 语义向量效果。

## 当前结果

| 方案 | Hit@1 | Hit@3 | MRR | 拒答准确率 | 错域率 |
|---|---:|---:|---:|---:|---:|
| 不使用 RAG | 0.00% | 0.00% | 0.000 | 100.00% | 0.00% |
| 基础词法检索 | 57.89% | 68.42% | 0.623 | 100.00% | 17.65% |
| 词法 + 领域过滤 | 63.16% | 68.42% | 0.658 | 100.00% | 0.00% |
| 查询扩展 + 领域过滤 | 73.68% | 78.95% | 0.763 | 100.00% | 0.00% |

## 决策

1. 领域过滤已进入生产链路，因为它消除了本数据集中的错域召回，并提升首位命中。
2. 查询扩展有明显收益，保留现有 LLM Query Rewrite；但本次确定性词表只用于实验，暂不把测试词表直接写入生产规则。
3. 本地词法检索仍漏掉“签收以后几天能退”“客服会问验证码吗”等表达，不能宣称当前召回已经完善。
4. 下一轮应在相同数据上比较 Chroma 语义检索、语义检索 + 领域过滤、Query Rewrite 和 Rerank，并单独报告模型失败率与端到端延迟。

完整逐样本报告可通过 `scripts/run_rag_ablation.py` 在本地 `outputs/` 目录重新生成；原始输出不提交到仓库。
